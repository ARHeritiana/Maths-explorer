## 4. Pipeline

Builders (`scripts/`): `build-tex-resources.py` (Première, Seconde, Terminale), `build-automatismes.py`, `build-stmg.py`,
`build-enrichment-latex.py`, `build-slides.py`, `extract-terminale-slides.py`, then `style-resource-pdfs.py`,
`finalize-resources.py`, `publish-sources.py` (chained by `restyle-changed.sh`). Findings:

- **P1.** Five near-identical `compile_pdf` functions (three passes, `-halt-on-error`, log scan), each with its own entry
  naming and edition switch.
- **P2.** No cache: a rebuild of one chapter recompiles the whole book (two editions, two languages).
- **P3.** Editions are selected four different ways: `\def\versionprof{1}` (Première), `\def\VERSIONPROF{1}` (Seconde),
  `\def\VERSIONELEVE{1}` with teacher as default (Terminale), `\def\EditionProf{false}` (STMG), `\def\PROFVERSION{}`
  (Automatismes), and the generated Enrichment files have no edition at all.
- **P4.** Two TeX engines (pdfLaTeX, XeLaTeX); the owner's default is pdfLaTeX.
- **P5.** Builders write into `dist/` and into `docs/*.json` ledgers directly; there is no build directory for products
  other than `build/tex` logs.
- **P6.** Post-processing (`style-resource-pdfs.py`) restyles compiled PDFs with PyMuPDF (header band, mint rule,
  colour mapping, up to 9.7 % scaling). With a shared TeX class the styling can live in TeX, and this step can go.
